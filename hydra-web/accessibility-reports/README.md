# Accessibility Reports

This directory contains automated accessibility testing reports for the Hydra web application.

## Report Types

### Accessibility Audit (`accessibility-report.html` / `.json`)
- Comprehensive WCAG 2.2 Level AA compliance check
- Generated by: `npm run a11y:audit`
- Uses: axe-core accessibility engine
- Includes: Page-by-page analysis, violation details, screenshots

### Keyboard Navigation (`keyboard-navigation-report.md` / `.json`)
- Tab order analysis
- Focus indicator validation
- Keyboard trap detection
- Generated by: `npm run a11y:keyboard`

### Color Contrast (`color-contrast-report.html` / `.md` / `.json`)
- WCAG AA and AAA contrast compliance
- Text element analysis
- Color combination suggestions
- Generated by: `npm run a11y:contrast`

### ARIA & Semantic HTML (`aria-semantic-report.md` / `.json`)
- ARIA attribute validation
- Heading hierarchy check
- Landmark region audit
- Form label verification
- Generated by: `npm run a11y:aria`

## Quick Reference

```bash
# Generate all reports
npm run a11y:all

# Generate individual reports
npm run a11y:audit      # Main accessibility audit
npm run a11y:keyboard   # Keyboard testing
npm run a11y:contrast   # Color contrast
npm run a11y:aria       # ARIA and semantics
```

## Understanding Scores

| Score Range | Rating | Meaning |
|-------------|--------|---------|
| 90-100 | ✅ Excellent | WCAG 2.2 AA compliant, minor improvements only |
| 70-89 | ⚠️ Good | Some issues to address, generally accessible |
| 50-69 | ⚠️ Fair | Significant accessibility gaps |
| < 50 | ❌ Poor | Major accessibility barriers |

**Production Threshold**: ≥ 90

## Violation Severity

- **Critical** 🔴: Fix immediately (blocks access)
- **Serious** 🟠: Fix before release (significant barriers)
- **Moderate** 🟡: Plan to fix (some difficulty)
- **Minor** 🔵: Best practice (minimal impact)

## CI/CD Integration

These reports can be generated automatically in your CI/CD pipeline:

```yaml
# .github/workflows/accessibility.yml
- name: Run accessibility tests
  run: npm run a11y:all

- name: Upload reports
  uses: actions/upload-artifact@v3
  with:
    name: accessibility-reports
    path: accessibility-reports/
```

## Common Issues

### Missing Reports
- Ensure dev server is running (`npm run dev`)
- Check test scripts completed successfully
- Verify write permissions on directory

### Stale Reports
- Reports are not auto-refreshed
- Re-run tests after making changes
- Check timestamps in report headers

### Test Failures
- Review console output for errors
- Check application is accessible at test URLs
- Verify authentication if testing protected pages
